# 显微镜（X-01）：外形、碰撞箱、贴图规格

**结论：好设计，而且已经改好了。** 显微镜现在不再是完整方块，而是一台由 5 个盒子拼出来的
台面仪器，可以四个朝向放置，碰撞箱与外形严格一致。

这份文档同时是"你改贴图/改外形"的说明书：**模型和碰撞箱的坐标必须成对修改**，
所以两边的数字都列在下面。

---

## 1. 现在这一版（方案 A，已在游戏里）

正面（模型没被旋转时的北面）朝向玩家，就像切石机那样：你把它放下，正面对着你。

| # | 零件 | from（起点） | to（终点） | 贴图 |
|---|---|---|---|---|
| 1 | 底座 | `1, 0, 1` | `15, 3, 15` | `#body` |
| 2 | 载物台 | `3, 5, 3` | `11, 6, 10` | `#body` |
| 3 | 立柱（后方） | `10, 3, 11` | `14, 16, 15` | `#body` |
| 4 | 横臂 | `5, 13, 5` | `14, 15, 15` | `#body` |
| 5 | 镜筒（含目镜） | `6, 9, 6` | `8, 16, 8` | `#glass` |

- 整体高度 16 像素（顶到方块上沿），底座 14×14 像素，站在台面上不占满一格。
- 底座底面写了 `cullface: down`，贴着地面或台面时那一面不渲染，省一点开销。
- 模型文件：`src/main/resources/assets/beyondtime/models/block/microscope.json`
- 碰撞箱：`MicroscopeBlock#NORTH_SHAPE`，是同样的 5 个盒子：

```java
Shapes.or(
        Block.box(1.0, 0.0, 1.0, 15.0, 3.0, 15.0),    // 底座
        Block.box(3.0, 5.0, 3.0, 11.0, 6.0, 10.0),    // 载物台
        Block.box(10.0, 3.0, 11.0, 14.0, 16.0, 15.0), // 立柱
        Block.box(5.0, 13.0, 5.0, 14.0, 15.0, 15.0),  // 横臂
        Block.box(6.0, 9.0, 6.0, 8.0, 16.0, 8.0));    // 镜筒
```

另外三条已经接好的机制：

- 只写了**北向**一套模型和一套碰撞箱，四个朝向由游戏按 `facing` 自动旋转
  （datagen 生成的 blockstate 里带 `y: 0/90/180/270`）。
- 方块本身带 `noOcclusion()`，所以它不会像完整方块那样把旁边的亮度压暗；
  光照按形状算（`useShapeForLightOcclusion`）。
- 没有碰撞的"空隙"依然不可穿过：碰撞箱就是外形，看到描边是什么形状，撞到的就是什么形状。

## 2. 怎么最快看到效果

| 你改了什么 | 怎么生效 |
|---|---|
| `models/block/microscope.json` | 游戏里 **F3 + T**，不用重启、不用重编 |
| `textures/block/*.png` | **F3 + T** |
| `MicroscopeBlock#NORTH_SHAPE`（Java） | 重开一次 `tools\dev-client.bat` |

模型文件是手写的、**不由 datagen 生成**（datagen 只生成 blockstate 指向它），
所以你可以放心地反复改那个 JSON，F3+T 就能看到新形状。

想边改边看，建议这样：

1. 双击 `tools\dev-client.bat` 进游戏，创造模式拿一个显微镜放下；
2. 切到窗口外改 JSON，回游戏按 F3+T；
3. 想换朝向：换个面再放一个，或者用活塞/结构方块都行。

> 改完模型记得回头确认 `NORTH_SHAPE` 的 5 个盒子是否还对得上，不然描边和实际外形会不一致。
> 懒得自己数就说一声，把新的 `from/to` 丢给我，我来同步两处。

## 3. 三套备选外形

三个方案的模型文件都已经放在 `tools/microscope-variants/`，切换只要两步：
把 JSON 覆盖过去 + 把 `NORTH_SHAPE` 换成下面那段。覆盖命令（在项目根目录执行）：

```powershell
Copy-Item tools\microscope-variants\b_tower.json src\main\resources\assets\beyondtime\models\block\microscope.json
```

### 方案 A —— 台面式（当前） · `a_desk.json`

高度 16，立柱在右后方，横臂伸到前方，镜筒吊在载物台上方。
**优点**：最有"显微镜"的辨识度，正反面明显，与贴图配合空间大。
**缺点**：顶到方块上沿，视觉上偏高。

### 方案 B —— 高塔式 · `b_tower.json`

立柱细而居中并且到顶，横臂从立柱往回伸，镜筒在最前、最长。

| # | 零件 | from | to | 贴图 |
|---|---|---|---|---|
| 1 | 底座 | `2, 0, 2` | `14, 2, 14` | `#body` |
| 2 | 载物台 | `3, 5, 3` | `11, 6, 9` | `#body` |
| 3 | 立柱 | `6, 2, 10` | `10, 16, 14` | `#body` |
| 4 | 横臂 | `4, 12, 4` | `10, 14, 14` | `#body` |
| 5 | 镜筒 | `5, 8, 5` | `7, 16, 7` | `#glass` |

```java
Shapes.or(
        Block.box(2.0, 0.0, 2.0, 14.0, 2.0, 14.0),
        Block.box(3.0, 5.0, 3.0, 11.0, 6.0, 9.0),
        Block.box(6.0, 2.0, 10.0, 10.0, 16.0, 14.0),
        Block.box(4.0, 12.0, 4.0, 10.0, 14.0, 14.0),
        Block.box(5.0, 8.0, 5.0, 7.0, 16.0, 7.0));
```

**优点**：左右对称（除镜筒外），四个朝向看起来差别不大，省贴图画工。
**缺点**：和"观察台"的印象弱一些，更像立柱仪器。

### 方案 C —— 矮台座 · `c_low_bench.json`

整体压到 10 像素高，像放在桌面上的一台老式黄铜显微镜。

| # | 零件 | from | to | 贴图 |
|---|---|---|---|---|
| 1 | 底座 | `1, 0, 1` | `15, 3, 15` | `#body` |
| 2 | 立柱 | `11, 3, 11` | `14, 8, 15` | `#body` |
| 3 | 横臂 | `4, 6, 4` | `14, 8, 15` | `#body` |
| 4 | 镜筒 | `6, 3, 6` | `8, 10, 8` | `#glass` |

```java
Shapes.or(
        Block.box(1.0, 0.0, 1.0, 15.0, 3.0, 15.0),
        Block.box(11.0, 3.0, 11.0, 14.0, 8.0, 15.0),
        Block.box(4.0, 6.0, 4.0, 14.0, 8.0, 15.0),
        Block.box(6.0, 3.0, 6.0, 8.0, 10.0, 8.0));
```

**优点**：不挡视线、放在实验室一排很整齐，方块上沿留白以后可以加"提示灯"之类的细节。
**缺点**：外形元素少，单靠形状不容易看出是显微镜，更依赖贴图。

### 还可以怎么变（说一声我就做）

- **载物台上放培养皿**：加一个 `has_dish` 方块状态，有皿时额外渲染一个皿的模型，
  放进/取出时外观跟着变。这个最值得做，但要多一个模型和一条 blockstate 属性。
- 只有底座 + 载物台 + 短镜筒（高度 8）的"便携式"。
- 双立柱、镜筒斜伸 45° 的"老式黄铜"造型（需要给元素写 `rotation`）。
- 底座做成 12×12、四角带脚，看起来"没铺满方块"。

## 4. 贴图规格（重点）

### 4.1 文件格式与尺寸

| 用途 | 尺寸 | 格式 | 路径 |
|---|---|---|---|
| 显微镜机身 | **32×32** | PNG，不透明 | `src/main/resources/assets/beyondtime/textures/block/microscope.png` |
| 镜筒玻璃 | **32×32** | PNG，可带透明 | `src/main/resources/assets/beyondtime/textures/block/microscope_glass.png` |
| 培养皿 | **32×32** | PNG，背景必须透明 | `src/main/resources/assets/beyondtime/textures/item/petri_dish.png` |
| 显微镜界面背景 | **256×256** | PNG | `src/main/resources/assets/beyondtime/textures/gui/microscope.png` |

都是普通 PNG（8 位 RGBA 像素图即可），不要用 JPG/WebP，也不要把图放进 `src/generated/`。
文件名全小写、用下划线，不要用中文名。

### 4.2 模型里贴图是怎么用的（决定你要画成什么样）

模型元素只写了 `"texture": "#body"`，**没有写 `uv`**，也就是说：

> **一个零件的一个面 = 整张贴图铺满一次。**

32×32 的贴图在模型里被当作 16×16 的坐标空间使用（0..16 对应整张图），
所以 32×32 完全没问题，只是分辨率更高、更细腻。

实际含义：

- `microscope.png` 画成"一块仪器外壳表面"就够了（金属底色 + 接缝 + 几个螺丝），
  它会被贴到底座、载物台、立柱、横臂的每一个面上。
- `microscope_glass.png` 只用在镜筒上，画成"玻璃筒 / 镜片"的表面即可，可以带透明。
- 想更精细（比如立柱正面专门画刻度、载物台专门画黑色台面），就在 JSON 里对应的 face 上
  加 `"uv": [0, 0, 8, 8]` 之类，把一张 32×32 切成多块分别取用 —— 需要的话我给你写示例。

### 4.3 培养皿贴图的注意点

培养皿是**扁平物品图标**，只画在 32×32 的画布里，**四角必须是透明**，否则游戏里会出现
一个灰色方块底。建议留 2~3 像素透明边距，圆形主体居中。

以后如果要在显微界面里画皿里的菌落，建议另开一张 32×32 的**覆盖层贴图**（例如
`textures/item/petri_dish_sample.png`，只有菌落不画皿），由界面叠在原图上，
这样皿和样本可以各自独立替换。

### 4.4 界面背景的固定坐标（不要自己挪）

界面背景是 **256×256**（和所有原版容器界面一致），可见面板画在**左上角的 176×166**里。
代码里的槽位坐标是定死的，画图时按这张表对位：

| 界面元素 | 面板内坐标（左上角为 0,0） |
|---|---|
| 标题文字"显微镜" | `8, 6` |
| 培养皿槽位 | `26, 21`（16×16） |
| 样本报告框（暂定） | `48, 18`，大小 120×48 |
| "物品栏"文字 | `8, 72` |
| 玩家背包 3 行 | `8, 84` 起，每格 18 像素 |
| 快捷栏 | `8, 142`，每格 18 像素 |

（那 176×166 以外的地方留透明没用，游戏不会绘制；但整张图必须是 256×256，
否则会被拉伸、所有槽位都会错位 —— 这就是之前界面错位的原因。）
