# 组织采样与基础生物分析仪（T-01 / T-02 / M-01）

> 本文记录**本轮已经落地**的采集器、密封组织样本、基础生物分析仪，以及开发方为它们
> 补全的设定。作者可以随时覆盖其中任何一条；改数值/名单不需要动代码的地方会特别标出。
>
> 相关：机器总表见 [MACHINES.md](MACHINES.md)，配方登记见 [RECIPES.md](RECIPES.md)，
> 知识系统见 [MACHINES.md](MACHINES.md) 第 0.1 节。

---

## 1. 这一轮玩起来是什么样

```
工作台做出采集器
   ↓
对名单里的生物补最后一刀
   ↓
掉落 1 个「密封组织样本」（不可堆叠，带来源与随机种子）
   ↓
把样本放进「基础生物分析仪」
   ↓
样本被消耗，界面里出现一份「部分分析报告」
   ↓
关掉界面 → 报告消失；要看别的，只能再采一份
```

两个刻意的限制：

1. **采集器只够采 3 个样本**：每次攻击磨损 1 点，击杀额外磨损 16 点，
   64 点耐久 = 3 × (1 + 16) + 15，第 4 个样本拿不到。这是设计好的，不是数值失误。
2. **基础分析仪不存档**：报告只活在打开的界面里。它不是"看完就忘"，而是"没法回看"，
   玩家得自己把有用的信息记下来。高级分析仪才会存档、可切换、可共享。

## 2. 采集器（T-01）

| 项 | 值 | 说明 |
|---|---|---|
| 耐久 | **64** | 见上面的 3 个样本算术 |
| 伤害 | **3 点**（含空手 1 点） | `ATTACK_DAMAGE = 3`，属性 modifier 写 `+2` |
| 攻击速度 | **-2.0** | 比剑慢，避免变成战斗武器 |
| 每次攻击磨损 | **1 点** | 原版 `WEAPON` 组件自动处理 |
| 击杀额外磨损 | **16 点** | `SamplerEvents` 处理 |
| 附魔 | **不可附魔** | 不给 `ENCHANTABLE` 组件 |
| 可采对象 | 实体标签 `#beyondtime:samplable` | 改名单 = 改一个 JSON |
| 掉落 | 1 个密封组织样本 | 只有**近战最后一击**才算；弓箭等投掷物不算 |
| 击杀判定 | `LivingDropsEvent` + `DamageSource#getDirectEntity` | 只在真的死亡时触发一次 |

**改名单**：`src/main/resources/data/beyondtime/tags/entity_type/samplable.json`。
加一个 `"minecraft:xxx"` 就多一种可采生物，不需要重新编译代码；数据包也能改。

## 3. 密封组织样本（T-02）

不可堆叠（`stacksTo(1)`），带 `beyondtime:tissue` 数据组件：

| 字段 | 类型 | 含义 |
|---|---|---|
| `entity` | `Identifier` | 生物类型 id，例如 `minecraft:enderman` |
| `analysis` | `none` / `partial` / `full` | 读到什么程度 |
| `seed` | `long` | 决定"这一次能看清哪几条特征"的随机种子 |
| `dimension` | `Identifier` | 在哪个维度采的 |

设计要点：

- **一个组件服务所有机器**：采集器、基础/高级分析仪、编辑仪、培养器、克隆舱都读它，
  不替每台机器发明一种样本物品（MACHINES.md 0.2）。
- **种子让报告可以两端重建**：服务端只同步"生物 + 种子 + 分析等级"，客户端用同样的
  算法算出同样的文字，不需要发字符串。
- **样本不产出资源**：不能吃、不能烧、不能合成；它只用来读。

## 4. 基础生物分析仪（M-01）

| 项 | 值 | 状态 |
|---|---|---|
| 耗时 | **不耗时** | 已确认 |
| 耗能 | **不耗能** | 已确认 |
| 样本 | 放入即消耗 1 个 | 已确认 |
| 结果留存 | **不存档**，关闭界面即消失 | 已确认 |
| 信息完整度 | **部分**：2 条特征 + 残缺基因码 | 本轮开发方补全，作者可改 |
| 外观 | 完整方块，正面朝向玩家，铸铁 + 黄铜 + 玻璃 | 本轮开发方设计 |
| 界面 | 200×240 面板，左侧样本槽，右侧/下方羊皮纸报告 | 本轮开发方设计 |

### 4.1 "缺哪些、留哪些"（本轮补全）

基础分析仪**一定给出**：

- 生物名称；
- 分类（末地人形 / 下界 / 亡灵 / 灾厄村民 / 水生 / 构造体……）；
- 基因片段：完整码有 2~3 段，基础分析只显示**前 2 段 + `??`**；
- 特征：从该生物的特征表里**按种子随机抽 2 条**；
- 一行明确的「信号缺失，无法读取」；
- 结论：「信息不完整。高级生物分析仪可以补全。」

基础分析仪**不会给出**：

- 完整基因码；
- 全部特征；
- 任何"结论性"的主线判断（例如伪古水菌的名字、猪灵僵尸化的完整机理）；
- 历史节点、配方、日志条目。

> 这样两份同种生物的样本可能看到不同的两条特征，玩家会想多采几次；
> 但又不会一次把底牌全翻出来。

### 4.2 报告是怎么算出来的

`TissueReport` 是纯函数：

```
(生物 id, seed, analysis) → 一行行文字
```

- 部分分析：`visibleTraits` 用 `new Random(seed)` 做部分 Fisher-Yates，取前 2 条；
- 完整分析：显示全部特征和完整基因码；
- 两端（服务端/客户端）算出的结果完全一致，所以不需要同步文字。

### 4.3 界面坐标（画背景/改版式时用）

背景 PNG 是 **256×256**，可见面板画在左上角 **200×240**。

| 元素 | 面板内坐标 | 大小/说明 |

```
末影人
分析程度：部分
分类：末地 · 人形
基因片段：E-01 / E-04 / ??
可读特征：
· 表皮遇水会迅速崩解，像被某种毒素侵蚀
· 瞬移后残留的紫色粒子可以被采样
· 信号缺失，无法读取
结论：信息不完整。高级生物分析仪可以补全。
```

## 5. 配方（本轮开发方设计，作者可改）

### R-04 采集器（无序合成）

```
玻璃瓶 ×3 + 铁锭 ×2 + 木棍 ×1
```

3 个玻璃瓶是作者确认过的部分；铁锭做取芯机构，木棍做推杆。
便宜是有意的：它是 progression 的第一把工具，而且三个样本就会坏。

### R-05 基础生物分析仪（3×3 有序）

```
铁锭   玻璃   铁锭
铁锭   铜锭   铁锭
空     红石   空
```

合计：铁锭 ×4、玻璃 ×2、铜锭 ×1、红石 ×1。
不用紫水晶：显微镜已经吃掉了紫水晶，分析仪应该在看完前几个样本后就能做出来。

完整配方登记见 [RECIPES.md](RECIPES.md)。

## 9. 作者验收清单

进游戏后按顺序试：

1. 创造模式页签里能看到 **采集器 / 密封组织样本 / 基础生物分析仪**。
2. 用采集器打末影人、猪灵、村民、监守者等名单内生物，最后一击后掉 1 个样本；
   打牛（在名单里）也掉；打不在名单里的生物（例如蝙蝠）不掉。
3. 第 1 个样本后采集器耐久掉 17；第 3 个样本后还剩 13 点；第 4 次击杀会把它打坏，
   而且**不会掉第 4 个样本**（16 点击杀磨损在样本释放之前结算）。
4. 样本鼠标悬停：显示"来源：末影人（主世界）""分析程度：未分析"。
5. 拿着样本右键分析仪：样本进槽、界面打开、样本被消耗、报告出现。
6. 同一种生物采 2~3 次，报告里的两条特征会换；基因码始终是"前两段 + ??"。
7. 关掉界面再打开：报告不见了（只剩"等待样本"）。
8. 报告底部出现"观察记录已更新"（第一次分析该生物时）。
9. 破坏分析仪：方块掉落，槽里的样本单独掉出来。
10. 工作台：3 玻璃瓶 + 2 铁锭 + 1 木棍 → 采集器；4 铁 + 2 玻璃 + 1 铜 + 1 红石 → 分析仪。
